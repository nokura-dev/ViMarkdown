### キーマップの回帰を防ぐために維持したもの

- キー解釈の条件分岐、JISの記号補正、macOS入力文字を採用する条件。
- 曖昧なキーをTextInputまたはKeyUpで処理する順序、保留の取り消し、非同期クリップボード操作を含む入力順序。
- 回数指定、コマンド実行、`$`・`h`・`l`・`d$`後のカーソル補正。
- `VimCommandChecks`、`MovementAuditChecks`、`LineEndEditingChecks`、`ParagraphNavigationChecks`、`NavigationChecks`、履歴・IME・フォーカス・ショートカットのテスト。

キーマップの純粋な解釈処理は、一時的な比較プログラムで194キー×8修飾キー構成×24種類のKeySymbol×7種類のmacOS入力文字（計260,736通り）を比較しました。記号キー判定・ネイティブ入力文字の採用判定・解釈した文字列は変更前後で一致しています。コマンド解析・実行部分も、空白を除いて変更前と同一であることを確認しました。

### テストの整理

変更前の2,203チェックから、重複した確認と集計を整理しています。

| 整理対象 | 変更と残した検証 |
|---|---|
| サンプルのコード文字ごとの同じ位置対応チェック | 全文字を引き続き検証し、221件を1件の不変条件チェックへ集約。失敗した原文オフセットも表示 |
| `ModeAlignmentChecks` 冒頭のページ・見出し位置合わせ16件 | 同じ位置合わせの性質を同スイートのページ切り替え検証と `PageInkAlignmentChecks` でも確認しているため削除。文字種・ページ行数・画面幅・表示倍率を扱う検証は維持 |
| ペイン幅が上限に達した後の同じドラッグ50回 | 上限到達後の追加ドラッグ1回に整理。最小幅・最大幅・初期幅への復元・ウィンドウ縮小の検証は維持 |

チェック数の減少は236件です。キーマップの回帰ケースは削除せず、既存の `--suite` オプションで対象だけを実行することもできます。

```sh
dotnet run --project tests/ViMarkdown.Checks --no-restore -- --suite VimCommandChecks,MovementAuditChecks,LineEndEditingChecks,ParagraphNavigationChecks,NavigationChecks
```

既存テストは676項目から606項目へ整理しました（70項目削減）。作業中に追加されたページ切り替え時の位置合わせチェック141項目も保持し、当時の合計は747項目です。

- 単体の `TextDocument` のUndo／Redo確認を削除。実ウィンドウでの履歴・カーソル復元チェックを維持。
- 見出しサイズと末尾改行の全組み合わせを、全見出しサイズ・各改行形式を含む代表ケースへ整理。
- フォーカス・履歴の同条件での反復回数を削減。複数回操作した後の位置・入力を引き続き確認。
- 重複する行移動・削除チェックを整理。表示移動は `NavigationChecks`、Vim操作は `VimCommandChecks`、改行形式は `LineBreakChecks` で確認。
