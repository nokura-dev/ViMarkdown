# 変更箇所からのテスト選択

`--affected` は影響するスイートを選択し、スイート名と理由を表示して実行します。`--affected --dry-run` は選択だけを行い、GUI初期化・テスト実行・成功記録の更新をしません。

## 全件実行の優先

ユーザーが全件実行を指示した場合は `--all` を使います。成功済みでも全スイートを実行し、`--affected`・`--suite` と併用しても全件を優先します。引数なしも全件実行です。CIと配布前の検証では自動選択を使いません。

`--suite` は従来どおりカンマ区切り・繰り返し指定・大文字小文字を区別しない名前指定に対応します。`--all` のない `--affected` と `--suite` の併用は、指示が曖昧になるためエラーにします。不明なオプションやスイート名もエラーです。

## 監視と対応表

監視対象は `src/`、`tests/`、`scripts/`、`.github/`、ルートのビルド設定、D2の CLI・ライセンス定義、テスト用Markdownです。`bin/`、`obj/`、`node_modules/`、成功記録、通常の説明文・生成画像は除外します。

`TestImpactRules.cs` の対応表は直接の呼び出しだけでなく、イベント・リフレクション・共通ヘルパー経由の影響も含めます。

| 変更例 | 対象 |
|---|---|
| `DocxExport.cs` | `DocxChecks` |
| `MarkdownExport.cs`・`ExportFileNames.cs` | MD出力・docx出力・D2出力 |
| `WorkspaceSearch.cs` | `WorkspaceSearchChecks` |
| Vimキー解釈・入力・移動・編集・macOS入力 | 画面操作の回帰スイート一式（IME・履歴・フォーカス・検索・ショートカット等も含む） |
| 個別のテストファイル | 対象スイート。`PageInkAlignmentChecks` はそのヘルパーを使う `ModeAlignmentChecks` も対象 |
| アプリ初期化・描画共通処理・DB・プロジェクト設定・テスト共通基盤・未登録入力 | 全スイート |

ファイルの追加・削除・名前変更は、登録済みのファイルを含めて全件実行します。新しい共通ヘルパー等を対応表へ登録し忘れても、黙って除外しません。スイートが追加されて成功記録がない場合も実行対象です。

## 成功記録

スイートごとに、影響する入力のSHA-256と実行条件を記録します。OS・CPU・.NETランタイム・SDK・Debug／Release・依存パッケージ・D2実行条件が変わると、全件を再検証します。`--d2` で指定した実エンジン検証と描画オプションの対象は、明示要求として必ず選びます。

記録は `.cache/checks/state.json` へ一時ファイルから置き換えて保存します。選択した全スイートが成功し、実行前後の入力が一致するときだけ更新します。失敗した場合は、途中まで成功していても更新しません。

ファイル集合・実行条件の全件基準は、全スイートが成功したときだけ更新します。一部の手動実行で、初回や環境変更後の全件実行を省略することはありません。記録が存在しない・壊れている・形式を認識できない場合も全件実行です。

## 古いビルドの取り違え防止

テストプロジェクトのビルド成功時に `check-build-inputs.txt` を出力します。起動時に現在のソース・設定・テスト用Markdownと照合し、不一致なら実行を止めます。ソース変更後は `--no-build` を使わずビルドして実行してください。ビルド・復元に失敗した結果を成功記録に反映することはありません。

## 選択機構の検証

`AffectedChecksChecks` は初回・無変更・個別変更・間接依存・キーマップ必須回帰・共通処理・未登録入力・追加／削除／名前変更・環境変更・部分成功・失敗後の再選択・全件優先・描画／実D2指定・引数エラー・記録破損・確認時の無書き込み・古いビルド・監視対象の除外を検証します。

対応表は静的解析による完全な依存関係の証明ではありません。判断できない共通処理は広く選び、全件実行をCI・配布前・明示指示時の最終確認として維持します。
